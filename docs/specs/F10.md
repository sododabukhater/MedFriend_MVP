# F10-lite — Document vault (approved and built 22 Nov 2026)

Owner decisions (22 Nov): the vault lives **inside My medicines** (a "Medicines | Documents" switch at the top;
the 4 bottom tabs stay); the patient can add **photos and PDF files** (up to 10 MB).

## Goal
One private place for the patient's lab results and prescriptions, next to their medicine list, tagged by type and
date, so they can find and show them at the doctor or pharmacy. The app never reads, interprets or comments on a
document (no medical advice). It is a tidy folder only.

## What the patient sees
- **My medicines** gets a big two-part switch at the top: **Medicines | Documents** (Medicines selected at first).
- **Documents** view:
  - Filter chips: **All · Lab results · Prescriptions · Medical reports · Other** (All selected).
  - The list, newest date first. Each row: a small preview (the photo, or a PDF icon), the type, the date
    ("18 Nov 2026"), and the optional name ("Blood test – Dr. Ahmad").
  - Empty: "No documents yet. Add a lab result or prescription." Filter with nothing: "No documents of this type."
  - A fixed main button **Add a document** (same place as "Add a medicine").
- **Add a document** (one screen, after choosing the file):
  1. Tap **Add a document** → the phone offers camera, gallery or files (laptop: a file picker). Photos and PDF only.
  2. The screen shows the preview (or the PDF file name) and asks:
     - **Type**: four big buttons (Lab result / Prescription / Medical report / Other). Required.
     - **Date of the document**: date field, today by default, cannot be in the future.
     - **Name (optional)**: short text, e.g. "Blood test – Dr. Ahmad".
  3. **Save** (while saving: "Saving document…"). Cancel goes back without saving.
- **Open a document**: tap a row → full screen view:
  - Photo: shown full width (can be zoomed with the phone's own pinch).
  - PDF: an **Open the PDF** button (opens it in the browser's own PDF viewer, new tab).
  - Type, date and name shown above; **Delete document** (asks to confirm); **Back**.
- Errors: wrong file type → "Only photos and PDF files can be added."; over 10 MB → "This file is too big (max 10 MB).";
  upload fails → "The document could not be saved. Try again."

## How it works
- Photos are shrunk in the browser before upload, but less than pill photos so the text stays readable:
  longest side **1600 px**, JPEG ~85 % (about 300 KB). Same canvas code as F4, no new dependency.
- PDFs are uploaded as they are (max 10 MB).
- Stored in a **private** Supabase Storage bucket `documents`, path `<user id>/<document id>.<jpg|pdf>`.
  Shown through signed links (1 day), made when the list loads, like F4.
- Deleting a document deletes its file. **Reset all data** also deletes all documents and their files.
- Text: English and Arabic, written natively (Arabic list below marked REVIEW-AR).

## Data (owner approves before applying)
Migration `2026112218xxxx_documents.sql`:
- Table `public.documents`: `id uuid pk default gen_random_uuid()`, `user_id uuid not null default auth.uid()
  references auth.users on delete cascade`, `doc_type text not null check (doc_type in ('lab','prescription',
  'report','other'))`, `doc_date date not null`, `title text` (≤ 80 chars), `file_path text not null`,
  `mime_type text not null`, `created_at timestamptz not null default now()`. Index on `(user_id, doc_date desc)`.
- RLS on: owner-only select / insert / update / delete (`user_id = (select auth.uid())`).
- Bucket `documents`: private, max 10 MB, `image/jpeg`, `image/png`, `image/webp`, `application/pdf`; the same four
  owner-only storage policies as `pill-photos` (first folder = the user's id).
- Demo account: `scripts/seed-demo.mjs` adds **two sample documents** (a "Sample lab result" PDF made by the script,
  and a sample prescription picture), so the professor sees a filled vault; it clears older demo documents first.

## Acceptance criteria (Playwright, headless, phone + laptop)
1. My medicines shows the Medicines | Documents switch; Documents shows the empty message and "Add a document".
2. Add a photo as a Lab result with a date and name → it shows in the list (preview, type, date, name) and stays
   after reload.
3. Add a PDF as a Prescription → it shows with a PDF icon; opening it shows "Open the PDF".
4. The list is newest date first; the filter chips show only that type (and the "nothing of this type" message).
5. The date cannot be in the future; the type is required before Save.
6. A wrong file type and a file over 10 MB are refused with the friendly messages.
7. Delete → confirm → the document and its file are gone.
8. Privacy: a second account cannot read or list the first account's documents (table and storage refuse).
9. Reset all data removes all documents.
10. Arabic: the screens show in Arabic, right to left.

## Out of scope
Reading or extracting values from documents, sharing documents (WhatsApp / doctor), adding documents to the F9
summary, folders, multi-page scans.
